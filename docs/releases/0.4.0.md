Quintess 0.4.0 runs on more computers, saves more safely, and copes much better with damaged PDFs.

## New downloads

- **macOS:** one app for Apple silicon and Intel Macs, on a disk image.
- **Windows on ARM:** a native ARM64 installer for Snapdragon laptops and other ARM PCs.
- **Linux:** an AppImage that runs on most distributions without installing, and a Flatpak bundle, beside the .deb and the tarball.

## Saving and recovery

- **Saving keeps the original.** Saving a document back to its own file adds your changes after the original bytes instead of rewriting the file. Edits that remove content (redaction, deleting pages, removing metadata and the like), protection changes and Save as still write a clean file, so removed content never hides in an earlier version. File > Save as > Save a clean copy writes a fresh file at any time.
- **Autosave and recovery.** While a document has unsaved changes, Quintess keeps a recovery copy (every minute by default; set it in Preferences). After a crash, a power cut or a forced shutdown, the next start offers to reopen it. Copies of protected documents stay encrypted.

## Damaged files

- **They open for reading.** A file Quintess can't edit, but can still display, now opens read-only, with viewing, searching, copying, reading aloud and printing, instead of failing. A banner explains why.
- **Repair.** File > Repair by rewriting with PDFium (and `quintess repair` on the command line) writes a clean copy that opens as a normal, editable document.
- **More files open normally:** passwords with accented and non-Latin characters on AES-256 files, files whose latest changes are damaged, streams with a wrong length, broken page lists, and encryption settings stored in unusual ways.
- **Tested against 1,446 real and deliberately broken PDFs** from the pdf.js test suite, with no crashes, and fuzzed with hundreds of thousands of mutated files. Both now run on every change.

## Fixes

- **Graphics start-up.** If OpenGL can't start on a computer, Quintess switches to DirectX/Vulkan (Metal on a Mac), and the other way round, instead of failing.
- **Mixed-DPI monitors.** Dragging the window between monitors with different scaling on Windows 11 works properly.
- **Typing in Chinese, Japanese and Korean** through an input method works better on Windows, Linux and macOS.
- Several crashes on malformed files, found by fuzzing, are fixed, and a very slow save on some large files now takes a fraction of a second.

## Known limitations

- The Windows installers and the Mac app aren't code-signed yet. Windows may show a SmartScreen warning; on a Mac, the first time, open System Settings > Privacy & Security and choose Open Anyway.
- The Mac, Windows on ARM, AppImage and Flatpak builds are built and tested automatically on those systems, but haven't been tried by hand yet. Please report problems on GitHub.
- Inside the Flatpak, scanning and conversion through LibreOffice or a browser aren't available.
- A file that makes PDFium hang while drawing can still stall page drawing for the rest of the session. A guard against that is planned.
